# 踩坑总表（P01–P45，共 46 条，含 P03b 等子项）

按"症状"检索。每条都给：**症状 → 根因 → 修法**。全部为本机 Rhino 8 实测，不是文档抄来的。

> 使用顺序：出问题先在这里搜症状词（"全是线框""静默返回 None""只铺半根"），
> 大多数时候 30 秒内能定位，比重新试参数快得多。

## A. 连接（最贵的坑，一卡就是几小时）

### P01 带参方法静默返回 None —— 看着成功，其实什么都没建
**症状**：`rs.AddPoint([0,0,0])` 返回 `None`；`rs.AllObjects()` 返回空或 0；
脚本一步步"跑完"，文档里空空如也。
**根因**：走了"裸 PyIDispatch"。pywin32 默认用 `METHOD|PROPERTYGET` 组合标志调用，
Rhino 8 的 .NET COM **拒绝这个组合**，不报错，直接返回 None。
**修法**：用 `scripts/rhino_conn.py` 的 `RSProxy` —— 强制 `pythoncom.DISPATCH_METHOD`
纯方法标志，并缓存 dispid。
**判别**：`rs.Version()` 能返回、但 `rs.DocumentName()` 返回 None → 100% 是这个。

### P02 `InvokeTypes ... 失败` 全线报错
**症状**：强类型包装（`IRhinoScript(disp)`）每个方法都抛 `InvokeTypes 失败`。
**根因**：同 P01 的另一面 —— 强类型包装内部仍用组合标志。
**修法**：同上，走 RSProxy。makepy 强类型是**备选**，不是首选。

### P03 出图全是线框 —— 模型没坏，是窗口跑到屏幕外
**症状**：`CreatePreviewImage` 出的图只有黑线/轮廓，着色模式也是线框；
连"一个平面 + 一个 mesh"的对照实验也只剩线。
**根因**：Rhino 主窗口被放在 `(-21333, -21333)`（屏幕外），
视口不参与 GPU 着色管线，只能软件画线；更极端时直接出**空白图**（P38）。
**修法**：**每次出图前** `ensure_window()`（`shot_views()` 已内置）。
**判别**：`rs.window_ready()` 返回 `主窗口在屏幕外 rect=(-21333, ...)` 即此。
2026-11-03 实测：用户同时开两个 Rhino，两个主窗口**都在 -21333**，
`probe_state.py` 一眼报出来 —— 所以体检一定要看这一行。

### P03b 同时开两个 Rhino → 改到了另一个文档
**症状**：脚本跑得很顺利，用户说"我的模型没变"；或改完发现动的是 `未命名`。
**根因**：本机常见"正活一个实例 + 空文档一个实例"（2026-11-03 实测两个 pid，
一个 `清华园驿站_树院_v1.3dm`、一个 `未命名`）。`Dispatch` 只给其中一个，**不保证是你要的**。
**修法**：动手前 `assert_doc(rs, "清华园驿站")`；不匹配就抛错停下，
让用户关掉多余实例，**不要盲改**。


### P04 必须用带 pywin32 的解释器
**症状**：`import pythoncom` 报 ModuleNotFoundError。
**修法**：用带 **pywin32** 的 Python 跑（WorkBuddy 托管 Python 或系统 Python 均可）
（managed 版缺 `pythoncom`，别用）。

### P05 Rhino 起不来 / 突然要认证
**症状**：`Dispatch` 反复失败、进程列表里根本没有 `Rhino.exe`；用户说"打不开"。
**判别顺序（只读，别改任何东西）**：
1. `psutil` 看有没有 `rhino.exe` → 没有 = **启动失败**，不是 COM 问题
2. `win32gui.EnumWindows` 按 pid 列顶层窗口 → 主窗口 `Afx:...:Rhinoceros` 全隐藏、
   唯一可见窗口标题含「授权」= **停在授权对话框**（不是崩溃）
3. 事件日志（`win32evtlog`）看 `Application Error` / `.dll` 名 + 异常码
**修法**：**只汇报，不动手**。见 P37 红线。

## B. 数据封送

### P06 颜色参数只吃打包整数
**症状**：`rs.ObjectColor(o, [0,0,0])` → `Type mismatch in parameter. Integer required.`
**修法**：`packed = R + G*256 + B*65536`（纯黑 = 0，纯白 = 16777215）。

### P07 GUID 不能塞进 `to_nested_variant_r8`
**症状**：`to_nested_variant_r8(guids)` → `ValueError: could not convert string to float: 'd'`
**根因**：Rhino 8 对象 ID 是 **GUID 字符串**（不是 Rhino 5/6 的整数）。
**修法**：那个函数只给点坐标用。要传对象集合，用 `rs.SelectObjects(list_of_guid)`
或逐对象调用。

### P08 `AddSrfPt` 裸 list 报"一维数组"
**修法**：`rs.AddSrfPt(to_nested_variant_r8(pts))` —— 走一次封送。
（`AddLoftSrf` / `AddMesh` 同理。）

### P09 `AddInterpCurve` 闭合环不要重复首尾点
**症状**：闭合处出现一个尖角/打结。
**修法**：点集只给 N 个（不重复第 0 点），靠 closed 参数闭合。

### P10 旋转体截面必须落在 XZ 平面
**症状**：环形梁/圈枋塌成一张扁平圆盘。
**修法**：截面点写 `[r, 0, z]`，绕 Z 轴旋转。Y 必须恒为 0。

## C. 几何（这几条直接决定"看着对不对"）

### P11 【致命】`AddPipe` 只铺半根曲线
**症状**：格网只铺到半径一半，外侧一大圈光秃秃；"这块结构怎么这么稀疏"。
**根因**：`AddPipe(curve, parameters, radii, ...)` 里 `parameters` **不是半径控制点**，
而是管子的**起止参数** —— 从 `parameters[0]` 一直铺到曲线末端。
传中点 `[mid]` → 只生成后半根。
**修法**：
```python
dom = rs.CurveDomain(cid)
rs.AddPipe(cid, [dom[0], dom[1]], [r, r], 1, 1)   # 整根恒半径
```
**项目里发生过 10 处，全部只有一半长**，前几版用户"认可的"其实都是半截杆件。

### P12 Z 向 offset 在近垂直面上等于没偏移
**症状**：陡坡上一片光板（瓦垄被埋进瓦面）、檐口冒出白边（下层膜穿出来）。
**根因**：`z += offset` 在法向上的投影随坡度变陡而趋近 0。
**修法**：沿**曲面法向**偏移。参数曲面用有限差分算 `surf_n(th, t)`，再 `p + n*offset`。

### P13 开放单面 mesh 的绕序 = 法线方向
**症状**：面在外面看不见，翻过去才看得见（或相反）。
**修法**：按"逆时针从法线侧看"排顶点；一片面算完先用 `rs.SurfaceNormal` / 目视确认。

### P14 clamp 造成"悬空"
**症状**：檐口永远离地 0.4 m，怎么改形体都飘着。
**根因**：`E_edge()` 末尾 `return max(z, 0.40)` —— 一行 clamp 把整圈抬平。
**修法**：软下限代替硬 clamp：
```python
z = 0.5 * (z + math.sqrt(z*z + 0.01))     # 平滑贴 0，不出硬棱
```
**教训**：用户说"怎么不着地/怎么悬空"，**先 grep 自己的 clamp 和 max/min**，别先改形体。

### P15 顶部读成"平盘 / 烟囱"
**症状**：屋顶顶端不是尖的，是一块平板；坡度一调陡就变烟囱。
**根因**：剪影在 99% 高度处的宽度**下限恒等于洞口直径** `2*R0`。
那块"平盘"就是采光口本身，调坡度永远消不掉。
**修法**：**洞口下沉**（火山口），不是调坡：
```python
z -= RIM_DIP * math.exp(-(t / RIM_SIG)**2)   # RIM_DIP=0.95, RIM_SIG=0.135
CREST_Z += RIM_DIP                            # 补偿总高不变
```
`RIM_DIP` 必须 > ~0.45，否则洞沿会抢回最高点，剪影退化成平口。

### P16 剖面母线是弧的，平视却读成"弧线起伏"
**症状**：用户说"顶面平视过去应该在一条直线上"，改了半天坡度还是弯。
**根因**：降坡用了 smoothstep + 幂 + 尖化指数，曲线中段凹 → 剖面是个"弓"。
**修法**：让**降坡与半径分配共用同一个幂**：
```python
r = R0 + (R - R0) * t**RT_POW
z = H + (E - H) * t**RT_POW      # 于是 z 是 r 的线性函数 -> 母线严格是直线
```
然后删掉所有中段调制项（起脊项、低频起伏项）。
**验收**：母线最小二乘拟合残差 < 0.1 m（一般方位）；开口方位因拱腿下探允许 0.3–0.8 m。

### P17 屋面与立柱"两层感"
**症状**：柱是一根独立编的筐，屋面梁在洞口断头、上段插几根悬空竹竿。
**根因**：两套几何各建各的，数量还对不上（24 肋 vs 64 梁）。
**修法**：**一条插值曲线连续走完"屋面段 + 筒身段"**，且柱肋数 = 屋面放射梁数（32/32），
保证每根屋面梁都能落到一根柱肋上。筒身编织通高铺满，别只铺下段。

### P18 中心柱做成"竹编灯笼"
**症状**：上下等粗、中间掐腰，看着像笼子，不像"被屋面吊着的一束竹子"。
**根因**：把剖面读成"散脚—收腰—张开"（沙漏），实物是**一路单调向上张开的喇叭**。
**修法**：`COL_PROFILE` 半径单调递增，无收腰；柱脚扎紧、柱顶张开接屋面内环
（`R0` = 柱顶半径，漏斗口就是柱顶张开处）。

### P19 臆造构件（最常见的"错得理直气壮"）
**本项目真实发生过**：自己加了两道竹坐凳、纪念石刻、渗水卵石坑、三块条形基础、
六块金属连接件、中心混凝土垫层 —— 然后把它们当设计的一部分渲染了四轮。
**纪律**：
- 只建**图纸/照片上能指认**的构件；
- 想在落地处"补个支墩让它站得住"，属于**改设计**，不是建模；
- 删构件时连带 `DeleteLayer`（只能删空图层 → 先清对象再删层）。

### P20 比例整体小了 1.47 倍
**症状**：形体对了，但跟图纸叠不上；高跨比总觉得怪。
**根因**：用"假设总高 4.78 m"反推比例尺 —— **循环论证**。
**修法**：读图内**比例尺刻度**做像素级量测：
```
刻度在 1639.5 / 1696.5 / 1783.0 / 1926.5 px，对应 0/2/5/10 m
四段互校 -> 28.70 px/m
```
竖向需 ×1.450、水平需 ×1.483 → 两个数接近 = **整体等比缩放**，不是比例错。
**缩放后必须同步重算相机**（P25）。

## D. 显示与出图

### P21 颜色只有**两层**，别信"三层"
| 通道 | 设置方式 | 谁读它 |
|---|---|---|
| 显示颜色（对象色 / 图层色） | `ObjectColor` / `LayerColor` | **线框 + 着色** |
| 对象材质 diffuse | `ObjectMaterialSource(o,1)` + `MaterialColor` | **渲染** |

- 线框和着色**永远一起变**（它们读同一个通道）—— 所以"只改一个"是不可能的。
- 曾三次误判"着色读全局定义、改什么都不动"，真因是**量颜色时把深色地面算进了模型像素**。
  **量颜色前先排除背景和地面。**

### P22 改图层颜色没生效
**根因**：`AddLayer` 对**已存在**的图层是**空操作**，构造函数的颜色参数被忽略。
**修法**：补一句 `rs.LayerColor(name, rgb(...))`。

### P23 `ViewDisplayModeProperty` 是**用户级全局**配置，跨文档持久
**事故**：早期为了让出图干净，遍历所有显示模式把 `ShowEdges / ShowIsocurves /
ShowMeshWires` 全写成 False → **线框模式一条线都画不出来（像素占比 0.00%）**，
而且重开 Rhino 仍在，之后打开的每个文件都中招。
**纪律**：**永不使用 `ViewDisplayModeProperty` 做临时修改。**
要调观感，只改**文档级**的东西（图层色 / 对象色 / 材质 / 视口显示模式）。
万一已经写坏：逐个模式出图、统计非背景像素占比定位，只恢复被改坏的那几个键。

### P24 视口的显示模式是**文档属性**
`rs.ViewDisplayMode(view, idx)` 存进 `.3dm`，打开即所见 —— 这是做"黑模/白模"的**正当做法**，
不碰全局。索引：**0 线框 / 1 着色 / 2 渲染**；越界索引**静默无效**（不报错，别以为设上了）。

### P25 视口会被"污染"：相机参数一样，拍出来完全不同
**症状**：同一组 CAM/TGT，上一张是全景，这一张变成特写。
**根因**：镜头长度（lens length）被上一次投影切换带偏了。
**修法**：每次出图前复位：
```python
rs.CurrentView(view)
rs.Command("_-SetView _World _Perspective")   # 透视
rs.Command("_-SetView _World _Top")           # 平面
```
**正交立面必须单独脚本跑**，不要混进透视出图流程。

### P26 缩放后忘同步相机 → 拍出一整幅格网
整体 ×1.47 之后壳体半径涨到 10 m，相机还在壳内 → 满屏格网。
**纪律**：任何全局缩放后，**相机距离按同一比例重算**，然后重新出图确认。

### P27 出图唯一可用接口
`rs.CreatePreviewImage(path, view, [w, h])` —— **文件名在前**。
`_ViewCaptureToFile` 在 COM 下产出**空白图**，别用。

### P28 保存：`-_SaveAs` 只吃裸文件名
`rs.WorkingFolder(folder)` + `rs.Command("-_SaveAs 裸名字")`。
带引号的绝对路径**会失败**。

### P29 渲染模式会背面剔除玻璃
从室内看玻璃是"没有"的，看到的是格网 —— 跟实景照片一致，不是 bug。
玻璃给 0.78 透明度，避免从室内看成一堵灰墙。

### P37 `ViewDisplayModeName` 在本机返回空 —— 别指望按名字找模式
**症状**：想"切到渲染模式"，用名字查索引拿到空值，于是没切上，出图还是着色。
**修法**：**按索引扫**，不要按名字：
```python
for i, v in enumerate(rs.ViewNames() or []):
    print(i, v, rs.ViewDisplayMode(v))     # 索引才是可靠入口
```
已知索引：**0 线框 / 1 着色 / 2 渲染**。越界索引**静默无效**（不报错，最容易误以为设上了）。
验证是否真的切上了：出图后跑 `ink_stats`，别靠"我记得设过"。

### P38 四张预览图**全空**（`NO INK`）—— 两个原因，都跟模型无关
**症状**：透视/平面/立面出图全是一整块背景色，量化返回 `NO INK`；
但 Rhino 里模型明明在。**2026-11-03 真实事故，四张全空。**
**根因（同时中了两条）**：
1. **主窗口被启动画面挡住**（`Rhinoceros 8` 289×164 的小窗 + 「Retrieving License Info」），
   主窗口 `Afx:...:Rhinoceros` 全部 hidden → 视口不在屏幕上 → 离屏渲染出空白。
2. **相机目标还是 `(0,0,0)`**，而模型包围盒中心在 `x=7.7` → 模型根本不在视野里。
**修法**：
```python
from rhino_conn import shot_views, window_ready, ensure_window
print(window_ready())                 # 先看主窗口在不在屏幕上
shot_views(rs, outdir, prefix, views=("Perspective","Top","Front","Right"))
# shot_views 内部：ensure_window -> SetView 复位 -> frame_all(包围盒) -> 出图 -> 空图自检
```
**纪律**：**出图全空时第一反应是"窗口/相机"，不是"模型没建出来"。**
`shot()` 默认 `strict=True`：主窗口不可见 / 文档 0 对象 → 直接抛错并说明原因；
没给 cam/tgt 时自动 `frame_all()`，从根上消掉"相机停在原点"。
⚠️ **不要用"数非背景像素"来判空** —— Rhino 视口是渐变底，空图也能算出上万个"墨点"
（实测空图 18907 / 有内容 6704），这个指标只能当诊断参考。

### P39 线框是**白线**看不见 —— 材料色被写进了图层色
**症状**：用户原话"我要的是黑线为什么你再调用 skill 出来的是白线"；
灰底上一片浅色线，量化 `NO INK`，看着像模型没建。
**根因**：把"材料自然色"直接写进**图层色**：白墙 `(241,239,235)`、白屋面 `(250,248,243)`、
浅场地 `(245,245,242)`。而**线框模式画的就是图层色** → 白底白线。
**修法（默认交付就做，别等用户说）**：
```python
from rhino_conn import black_lines
black_lines(rs)          # 对象显示色 = 黑；图层色保留材料色
# 回退：restore_bylayer(rs)
```
**口诀**：给**眼睛看线**的颜色 ≠ 材料本身的颜色。材料色只能进材质/图层，
线色必须单独压黑。详见 `styling.md` §1。

## E. 交互与环境

### P30 `rs.Command` 等待输入 = 卡死
**症状**：脚本跑了 7 分钟没动，Rhino CPU 0.00s —— 空闲但 Python 卡在 COM 等待。
**根因**：`-_Open` 在**有未保存改动**的文档上弹了保存框；命令行等用户输入。
**纪律**：
- 调 `-_Open` / `-_SaveAs` 前先 `rs.DocumentModified()`，为 True 就**停下来问用户**；
- 已有脚本 rescue：`WScript.Shell.AppActivate("Rhinoceros")` + `SendKeys("{ESC}")`。

### P31 一次改多处会静默丢改动
同一份文件在同一批里发多个编辑，各自基于旧快照写回，**最后写入者胜**，
丢哪几处是随机的（实测一次丢 3 处）。
**修法**：串行改，或合并成一次大编辑；改完**双向 grep**（present + absent）。

### P32 本机 shell 的坑
- Git Bash 的 `dirname/head/ls/grep` 偶发 `command not found`，**管道不可靠**；
  输出一律**重定向到文件再读**。
- PowerShell 原生命令返回非零退出码会**中断整段脚本**，一次调用只做一件事。
- 中文经 PowerShell 重定向会乱码 → 让 Python 脚本自己写 UTF-8 文件。

### P33 送回收站不要永久删除
路径含中文时 `SHFileOperationW` 常返回 `rc=2(ERROR_FILE_NOT_FOUND)`，
**但文件其实已经进回收站** → 以"文件是否还存在"为最终判据。

### P40 启动卡在「插件程序载入失败」——旧插件 vs 新 Rhino
**症状**：双击 Rhino 半天不进主界面，弹「插件程序载入失败 — D5Conv.rhp」；
点了之后 Rhino 才继续启动，但**每次启动都弹**。
**根因**：`D5Conv.rhp` 是 2025-12 编译的旧版 D5 LiveSync，
而 Rhino 已在 10-09 升到 **8.31.26126** → 版本不匹配，加载失败并阻塞启动。
**处置**：
- 弹框上点**「是」**（＝本次不加载该插件）是安全的，想用 D5 时去官网装新版 LiveSync；
- **不要**为了"让它安静"去删 `AppData\Roaming\McNeel\...\Plug-ins` 下的文件 —— 那是用户装的东西；
- 判断"Rhino 打不开"时，**先枚举窗口**：如果唯一可见窗口是插件报错框，那就是它，不是授权、不是模型。

### P41 「保存改变为 未命名?」——三个按钮，别替用户选
**症状**：截图里一个模态框问「保存改变为 未命名?」，Rhino 卡住不动。
**根因**：**关闭/新建/打开**一个 `DocumentModified=True` 的文档时必弹。
这是**用户的活**，不是自动化能代答的：点「是」会再弹另存为，点「否」直接丢改动。
**纪律**：
1. **绝不自动点「否」** —— 那可能把用户几小时的建模直接扔掉（本项目 61 个对象就差点这样）。
2. 自动化脚本碰 `-_Open` / `-_Close` / `-_New` 前，先 `assert_clean(rs)`；不干净就**停下问用户**。
3. 需要保命时先 `save_as()` 另存到 `_build/未命名_抢救副本.3dm`，再谈关不关。
4. 已经卡住：`rescue()` 发 ESC（只解自己的卡，不要抢用户正在做的操作）。

### P42 「保存」三连坑——`-_Save` 卡死、覆盖同名静默跳过、返回值说谎（2026-11-03 驿站项目实测）
**症状**：改完图层色+材质后 `rs.Command("-_Save")` 卡死 COM（脚本超时被杀）；
换 `save_as()` 覆盖同名 v4，返回 ok=True 但**文件 mtime 没变**——根本没写盘。
**根因**：
1. `-_Save` 对已存在文档可能弹模态框（自动保存/备份类），COM 侧表现为无限等待；
2. `-_SaveAs` **静默拒绝覆盖同名文件**（脚本模式下不弹框，直接不执行）；
3. `save_as()` 的成功判据是 `os.path.exists(path)` —— 文件本来就存在时**恒为 True**，纯谎言。
**修法**：
1. 保存后必须做 **mtime 硬校验**：`os.path.getmtime(path) >= time.time()-30`，
   新文件不新鲜就是没写成；`save_as` 的返回值只对"新建"可信。
2. **永远另存新版本号**（skill 流程 §⑥ 本来就这么要求，这是血泪印证），不覆盖。
3. 保存卡死：`rescue()` 发 ESC，文档还在内存里（modified=True），改存新名号即可。

### P43 改文档的操作必须"单脚本一口气跑完"——跨脚本状态必丢（2026-11-03 驿站项目）
**症状**：第一个脚本 Open v4 → 改图层/材质 → 卡在保存被杀；第二个脚本重连时
附着实例 doc='' / objects=0，`-_Open` 也静默失效（30s 轮询 objects 恒为 0）——
实例处于"COM 活着但命令不执行"的坏状态，内存里的改动全丢。
**根因**：本机 Rhino 会**随机崩溃重启**（实测一天 4+ 次），且多实例下
`Dispatch` 连到哪个实例不可控；实例重启后 `DocumentName()` 返回 ''、`-_Open` 被吞。
**修法**：
1. **Open → 改 → 存 → 验证，写进同一个脚本一口气跑完**，中途不留"下个脚本继续"的窗口。
2. 每步硬校验：Open 后轮询 `AllObjects` 数量（≥60 才算就绪，别信 DocumentName）；
   保存后校验 mtime；出图后校验文件 mtime（CreatePreviewImage 也会静默失败）。
3. 实例彻底坏掉（Open 30s 无响应）：杀进程重拉（仅限自动化自己拉起的实例；
   动手前 tasklist 确认全机进程数，用户正开着的实例绝不能碰）。


### P44 渲染模式"整栋楼都是透明的"——`MaterialTransparency` 污染共享材质槽（2026-11-04 实测）
**症状**：切到 Render 模式，模型像玻璃一样透过去能看见背面；回读
`rs.MaterialTransparency(rs.ObjectMaterialIndex(o))`，**所有对象都是 0.82**。
用户原话："为啥渲染模式下是全透明"。

**根因**（不是显卡、不是渲染器、不是"白对白"）：
为了做玻璃，写了这么一段：
```python
mi = rs.AddMaterialToObject(glass_obj)      # ← 对象已有材质时，返回的是【已有槽位】
rs.MaterialTransparency(mi, 0.82)           # ← 这个槽位可能被整批对象共用
```
`AddMaterialToObject` 对**已有材质**的对象并不新建，而是把现有槽位返回；
该槽位一旦被多个对象共用，设一次透明度 = 整批对象一起变透明。
本项目 1266 个对象全中招，看起来就是"整栋楼透明"。

**修法**：
1. 设完**必须回读复核**：`audit_materials(rs)` 返回空 dict 才算过。
2. 一键兜底：`reset_materials(rs, site_layers=("场地",))`
   （全模型一把白材质 + 场地走图层色 + 背景改灰，一次到位）。
   或直接跑 `scripts/fix_render_materials.py`。
   ⚠️ 别指望"按组给物体材质染不同颜色"：`ObjectMaterialIndex` 的槽位会被多个对象共用，
   分组染色最后是"后处理的组赢"，回读会发现屋面吃了玻璃的颜色。分组只能用**图层色**。
3. **素模里玻璃不要默认开透明**。宁可给一把淡灰不透明材质——出图时再手动开。
   素模的玻璃本来就是"一块面"，透明反而让室内结构变成噪点。

**判断口诀**：只要"整批对象同时透明"，100% 是材质索引被共用，
不要去查环境贴图、显隐、图层透明度。

### P45 白模在 Render 模式"看不见"≠ 透明——纯白对纯白（2026-11-04）
**症状**：模型不透明，但切到渲染模式后几乎看不见，只有极淡的轮廓。
**根因**：白模材质 `(255,255,255)` + Rhino 默认渲染背景**纯白**，没有对比。
**修法**：
```python
render_bg(rs)                       # 背景改中性灰 (186,188,190)
# 或手动：rs.RenderColor(1, packed(186,188,190))
```
**为什么不做更暗的背景**：素模靠"白形体 + 灰底 + 软阴影"读体积，背景一暗，
模型边缘就糊；灰底 (180~195) 是这套观感的甜点。这条是**文档级设置**（Rhino Render 背景），
不是 `ViewDisplayModeProperty` 那种全局显示模式属性，不会踩 P23。

**验收**：出图后看直方图，模型像素 avg 应 > 200 且背景 ≈ 186，
两者拉开 60 以上才叫"看得见"。
